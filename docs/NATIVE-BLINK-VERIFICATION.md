# One native pass: measured attachment, appearance and lash correction

Use only the incoming model as the geometry source. Read the repository URL and exact revision from runtime configuration, clone and verify that revision, and run its Python and Node tests before and after the input-fitted adapter. Keep descriptions generic. Preserve previous failed artifacts; do not load their geometry as the new construction basis.

1. Inspect the actual input format, transforms, topology, source identifiers, image bytes, UV corners and existing rig. The direct SmartMesh input can be an FBX without an armature. Derive a working frame and canonical correspondence; do not copy prepared-GLB indices, object names or joint assumptions. Separate actual blue eye surfaces, dark lash bands, skin collars and uncertain parts by geometry and texture. Record original open boundaries as inherited limitations.
2. Freeze actual visible opening probes from true eye visibility and the back-facing head surfaces seen through the socket. Keep exterior front skin and free lash wings separately identified. A construction envelope is not an anatomical attachment loop. Do not use the depth of a far back wall as the eyelid-front depth.
3. Reuse the pinned eyelid surface constructor with the measured envelope and actual stationary-eye obstacle. Fit its dimensions from the input. Do not include the protected source skin in a global depth floor that pushes the intended attachment row off the skin.
4. Obtain real source-skin triangle/barycentric bindings for the fixed outer row. Choose the appropriate upper or lower exterior source-skin region, so a nearest projection does not jump across the aperture to the opposite wall. Apply the fixed outer transition while retaining the corresponding moving inner rail.
5. Weld only generated vertices identical throughout their complete exported trajectories. Reject every remaining generated neutral, knot or interval degeneration; none is an inherited source defect. Preserve all original source vertices and faces.
6. Call `append_skin_transition_strips` with the fixed boundary in order, actual source skin triangles, canonical source IDs, source sample bindings and input-fitted route limits. Its complete-edge certificate must pass after float32 conversion. Preserve actual source triangle/barycentric provenance. Do not replace this with an anchor-only or fixed-position test.
7. Apply measured projected-triangle clearance **after** attachment. Hold the source boundary, every fixed transition vertex, and the fitted inner-rail trajectories unchanged. Sample the actual LINEAR controller within its knot intervals, not only at the knots. A static free-vertex correction can satisfy all supplied samples without disturbing attachment. Reject unresolved fixed constraints or an offset exceeding the declared input-fitted limit. This is not an all-angle collision certificate.
8. Reuse the measured skin appearance module. Geometry bindings and clean skin-color reference samples are different roles: source skin around the eye can contain baked eyeliner. Transfer linear COLOR values from appropriate surrounding skin; preserve measured boundary color deliberately and record the blend into the new skin interior. Do not interpolate unrelated source atlas UV coordinates across generated triangles. Keep original image bytes, UVs and material bindings unchanged on the original source.
9. Ensure each generated closed core has consistent outward winding. The old upper cores were inward. Orient fixed open transition faces toward the actual source-skin normal. Separate their shading domains from the closed core, and export explicit NORMAL and normal morph targets. Keep original source NORMAL bytes and only add the measured lash normal changes. Report between-knot normal interpolation error rather than claiming perfect shading from unit-vector checks.
10. Reuse the measured original-lash transfer and contact-role helpers. Preserve whole source components, canonical seams and source appearance. Distinguish static canthi/wing contacts from contacts carried by the moving lid rail and incidental back-wall overlap. Check actual carrier geometry, edge strain and continuous triangle areas. Do not fix every neutral contact to static head skin or force a free wing tip to lie on a moving seam.
11. Export the actual candidate once with runtime head binding on the generated geometry. Verify the sealed GLB after reimport: source bytes/attributes, image bytes, source hierarchy where present, finite weights, independent controls, stationary eyes, true lid underlay excluding lashes, complete source-boundary attachment, neutral reset, generated degeneracy and continuous intervals. Keep surrounding skin-superset counts separate from actual eye/cavity exposure.
12. Run native visual verification in the Lab's supplied current Blender only. `native_render_verification.py` accepts runtime paths, source/candidate transforms, measured camera/light specifications and actual controller names. It records the supplied Blender version and renderer. Use matched neutral front/oblique/profile and eye close-ups, independent and bilateral intermediate/full closures, and between-knot samples. Optional winding and flat-shading ablations reimport the same sealed candidate and never export another model.
13. Inspect the actual native renders for floating boundaries, detached/torn lashes, black bands, blocky or inverted shading and remaining exposed eyes. Differentiate original baked ink from newly generated material or geometry errors using first-hit ownership and material evidence. Numeric closure is not a visual-quality certificate. If a required visual or numeric gate fails, publish the evidence and editable diagnostic scene, withhold the primary handoff, and stop. Do not launch another construction pass.

The native render helper is syntax-checked source only; it has not been executed in the VM. No VM Blender installation, download or runtime execution is part of this workflow. The one native pass must provide the final renderer evidence.
