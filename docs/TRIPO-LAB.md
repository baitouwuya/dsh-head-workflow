# Using the public repository in a Tripo Lab node

This phase is pending publication by the operator. No repository URL, commit, Lab download route or Lab runtime capability is assumed here.

After the operator supplies the public URL:

1. Read the actual public repository and pin a commit. Verify its source hashes against the published manifest. Never embed GitHub credentials in a Lab prompt or source file.
2. Use a new `dsh-` canvas or the explicitly authorized existing canvas scope. Record its baseline and the credit balance before a paid run.
3. Attach the authorized original input asset. Do not upload an internal reference avatar or any unrelated local asset. The profile hash must match the supplied input or the run must stop for a fit review.
4. Ask Lab to inspect its available Blender/Python and repository retrieval tools. Use the actual tool contracts exposed there. If repository access, a supported Blender runtime or the input artifact is unavailable, report that limitation. Do not claim this guest's filesystem or host Blender is reachable from Lab.
5. Run the repository entry point with explicit input, profile and fresh output paths that exist in the Lab environment. Paths in the template below are placeholders to be resolved from actual Lab artifacts.
6. Retrieve the build manifest, geometry audits, output GLBs, control manifest and logs. Record the ending balance and observed cost. Run the exported asset through the included browser harness locally if Lab cannot render WebGL2. Inspect the sheet before accepting the rebuilt head.

## Lab task template

> Use the public repository REPOSITORY_URL at commit COMMIT_SHA. Inspect its README and VERIFICATION.md first. Rebuild the supplied original character with head_tool.py using the fitted original-character profile. Preserve the source asset and every existing canvas record. Work only in the authorized new output scope. Use the attached input asset's actual local artifact path. Run Blender in a fresh process, then the included structural and anatomy checks. Return the generated head and integrated GLBs, control manifest, build manifest, all check results and logs. Stop on an input-hash mismatch or failed geometry check. Do not invent repository access, tool results or output associations; report any missing capability. Do not publish the resulting assets.

The workflow is procedural; a public repository URL alone does not prove that Tripo Lab can execute it. The first canvas run must establish that capability from observed results. No canvas action has been performed by packaging this folder.
